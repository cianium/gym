## آزمون‌هایی که در محیط فعلی انجام نشدند
- `php tests/smoke.php` با خطای `could not find driver` متوقف شد؛ `PDO::getAvailableDrivers()` لیست خالی است. این **محدودیت محیط بررسی** است و نه اثبات خرابی migration. هیچ ادعایی درباره موفقیت واقعی دیتابیس یا PHPUnit مطرح نیست.
- تست یکپارچه MySQL/PostgreSQL، اجرای Feature tests بر دیتابیس واقعی، رزرو هم‌زمان واقعی با چند worker، پاسخ API واقعی ملی‌پیامک، پرداخت و callback واقعی، backup/restore در دیتابیس جداگانه، مرورگرهای موبایل و تست فشار اجرا نشده‌اند.
- با وجود سیاست‌های اضافه‌شده، تأیید نهایی امنیت نشست‌ها و ممیزی آسیب‌پذیری وابستگی‌ها همچنان باز است.

## ریسک‌ها و تصمیم انتشار
**NO-GO برای مشتری واقعی؛ GO فقط برای Staging ایزوله.**

دلایل: عدم تأیید تراکنش هم‌زمان/پرداخت/اعلان واقعی، نبود تست بانک اطلاعاتی، و نبود سورس React/TypeScript برای تغییرات اساسی فروشگاه/سایت عمومی. فروشگاه فعلی برای سازگاری از مسیر خرید مهمان استفاده می‌کند؛ گزینه `FITNESS_REQUIRE_VERIFIED_CHECKOUT` پیش‌فرض `false` است. برای الزام OTP همه خریدها ابتدا UI فروشگاه بازسازی و آزموده شود.

بکاپ امضاشده **رمزگذاری‌شده نیست** و اکنون حاوی اطلاعات کاربران و هش رمز عبور است؛ این بکاپ را هرگز در `public_html` یا فضای بدون رمز نگهداری نکنید.

## مسیر بعدی انتشار
1. ایجاد Staging در cPanel با PHP 8.3+، MySQL و افزونه‌های کامل؛ دیتابیس و تنظیمات جداگانه.
2. حفظ `.env` و `storage` در نصب فعلی و گرفتن بکاپ خام MySQL و فایل‌ها پیش از هر ارتقا؛ migrationها با `php artisan migrate --force`.
3. اجرای تست‌های PHPUnit و smoke، سپس آزمون رزرو هم‌زمان و جداسازی دو ورزشکار.
4. دریافت پاسخ مستند و واقعی MeliPayamak، بررسی قالب OTP یک‌متغیری و تأیید جلسه سه‌متغیری؛ بررسی `unknown` بدون ارسال دوباره خودکار.
5. تست درگاه و callbackهای تکراری، بکاپ و restore، UX موبایل، و سپس تصمیم GO/NO-GO مجدد.
