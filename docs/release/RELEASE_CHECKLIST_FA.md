# چک‌لیست تحویل و پذیرش نسخه

این نسخه ابتدا باید روی یک دامنه یا زیردامنهٔ staging نصب شود. فایل‌ها را مستقیماً روی سایت فعال مشتری جایگزین نکنید.

## ۱. کنترل فنی پیش از نصب

- PHP نسخه ۸.۳ یا جدیدتر و افزونه‌های `pdo_mysql`, `mbstring`, `openssl`, `xml`, `fileinfo`, `curl`, `gd` و `zip` فعال باشند.
- MySQL 8+ یا MariaDB 10.6+ با دیتابیس و کاربر اختصاصی آماده باشد.
- `laravel_core` خارج از Document Root و فقط `public_html` در دسترس وب باشد.
- HTTPS معتبر فعال و `APP_DEBUG=false` باشد.
- داخل `laravel_core` اجرا شود:

```bash
composer validate --strict
composer test
composer audit --locked
```

خروجی تست داخلی باید شامل `OK 7 smoke tests passed` باشد. اگر `composer audit` advisory بحرانی یا سطح بالا گزارش کرد، تحویل متوقف و dependency اصلاح شود.

## ۲. سناریوی پذیرش مدیر

1. نصب با setup token انجام و فایل token پس از موفقیت حذف شود.
2. اجرای دوباره نصب‌کننده خطای `ALREADY_INSTALLED` بدهد.
3. ورود، خروج و تغییر رمز مدیر انجام شود.
4. برند، SEO، پروفایل مربی و رنگ‌ها ویرایش و پس از refresh حفظ شوند.
5. محصول دیجیتال و فیزیکی ساخته، ویرایش، بایگانی و حذف شوند.
6. تصویر معتبر آپلود و فایل نامعتبر یا بزرگ رد شود.
7. فایل خصوصی PDF به محصول دیجیتال متصل شود.
8. پست و نظر ایجاد و فرایند تأیید نظر بررسی شود.
9. backup صادر و restore فقط روی staging آزمایش شود.
10. بازنشانی محتوا پس از backup آزمایش شود؛ سفارش و پرداخت آزمایشی باید باقی بمانند.

## ۳. سناریوی پذیرش مشتری

1. فروشگاه و جزئیات محصول در موبایل و دسکتاپ باز شوند.
2. قیمت، تخفیف، هزینه ارسال و جمع نهایی با محاسبه دستی تطبیق داده شوند.
3. موجودی محصول فیزیکی هنگام شروع پرداخت رزرو و در پرداخت ناموفق آزاد شود.
4. پرداخت sandbox برای هر درگاه مورد استفاده تا callback نهایی طی شود.
5. سفارش با شماره موبایل و توکن مالکیت نمایش داده شود و بدون آن قابل مشاهده نباشد.
6. دانلود محصول دیجیتال فقط پس از پرداخت موفق، تا سقف تعداد و زمان مجاز انجام شود.
7. فرم مشاوره، like و نظر در موبایل آزمایش شوند.

## ۴. کنترل UI و دسترسی‌پذیری

- اندازه‌های ۳۲۰، ۳۷۵، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل بررسی شوند.
- Chrome، Firefox و Safari یا iOS Safari آزمایش شوند.
- صفحه با Tab قابل پیمایش و focus روی همهٔ کنترل‌ها قابل مشاهده باشد.
- zoom مرورگر ۲۰۰٪ باعث قطع متن یا پنهان‌شدن دکمه‌ها نشود.
- حالت reduced motion، پیام آفلاین، متن‌های بلند فارسی و صفحه‌کلید موبایل بررسی شوند.
- کنتراست متن‌ها و پیام‌های خطا در نور کم و زیاد خوانا باشد.

## ۵. نسخه پشتیبان و بازگشت

پیش از انتشار، از دیتابیس و هر دو پوشهٔ `laravel_core` و `public_html` نسخه پشتیبان بگیرید و checksum آن را ثبت کنید. اگر پس از انتشار خطای بحرانی رخ داد:

1. سایت را در maintenance قرار دهید.
2. فایل‌های نسخهٔ قبلی را بازگردانید.
3. فقط اگر migration جدید ناسازگار اجرا شده، دیتابیس قبلی را restore کنید.
4. cache پیکربندی را با `php artisan optimize:clear` پاک کنید.
5. صفحه اصلی، ورود مدیر و یک سفارش قبلی را کنترل و سپس maintenance را غیرفعال کنید.

## ۶. معیار تحویل نهایی

تحویل زمانی تأیید شود که smoke test، audit وابستگی‌ها، پرداخت sandbox، backup/restore روی staging و چک UI مرورگرهای هدف همگی موفق باشند و مشخصات درگاه، SMTP، دامنه و حساب مدیر متعلق به مشتری باشند.
